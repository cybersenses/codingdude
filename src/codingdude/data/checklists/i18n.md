# Internationalization (i18n) checklist

As of: 2026-09-20
Source: https://raw.githubusercontent.com/msitarzewski/agency-agents/main/engineering/engineering-i18n-engineer.md
Use when: building software that must work across languages, scripts, or regions.

## Checklist
- [ ] Zero hardcoded user-facing strings; every string externalized with a translator description ("Book" — noun or verb?).
- [ ] No string concatenation in messages: word order differs per language. Complete ICU messages with named placeholders only.
- [ ] Plurals via CLDR/ICU `{count, plural, ...}` categories (always include `other`) — never `count === 1` ternaries. Arabic has 6 forms; Japanese has 1.
- [ ] All dates/numbers/currencies/lists/relative times through `Intl`/CLDR-backed APIs; hand-rolled formatters are defects.
- [ ] Layout in logical CSS properties (`margin-inline-start`, `text-align: start`) so RTL needs no stylesheet fork; `dir="auto"` isolation on user-generated content; directional icons flip, logos don't.
- [ ] Text expansion budgeted: labels can grow 100–200%, sentences ~35–50% (German/Finnish) — flexible containers, min-width not width, truncation decided per message.
- [ ] Unicode end-to-end: NFC-normalize on input, locale-aware collation for sort/search, truncate on grapheme clusters (never bytes), case changing always locale-aware.
- [ ] Locale from user preference + `Accept-Language` negotiation with a deliberate fallback chain (`pt-BR → pt → en`) — never IP geolocation alone.
- [ ] Pseudo-localization wired into CI: accented transform + 40% padding + brackets exposes encoding bugs, truncation, and hardcoded/concatenated strings — fail the build, not the launch.
- [ ] Per-locale launch gate: RTL walkthrough, expansion review on dense screens, formatting spot-check, native-speaker pass.

## Failure modes
- `"You have " + n + " items"` — untranslatable in half the world's languages.
- Polish plural forms breaking the ternary ('pliki' vs 'plików').
- Byte-based truncation corrupting multi-byte characters.
- A Hebrew username scrambling surrounding Latin punctuation (missing bidi isolation).

## Rejected
- TMS program management, mobile message-format mapping, font/typography depth.
